## 배포 구조 정리

운영 구조를 Docker Compose 기준으로 정리했습니다.

```txt
Nginx 443 포트
  -> 프론트엔드 컨테이너 127.0.0.1:3000
  -> /api/* 요청은 백엔드 컨테이너 127.0.0.1:8080

백엔드
  -> Oracle Cloud DB
  -> OpenCV 컨테이너 http://opencv:8000
```

기존 `/var/www/calpeace` 정적 배포 방식은 예전 방식으로 남기고, 현재 운영
문서는 Docker 컨테이너 기준으로 변경했습니다.

## CI와 Docker

- Docker workflow를 서비스별로 분리했습니다.
  - backend
  - frontend
  - opencv
  - native CI
- Docker 이미지 태그는 `sha-<짧은 git sha>`를 사용합니다.
- `dev` 또는 `main`에 push되면 VM `.env`의 이미지 태그를 자동 갱신합니다.
- 실제 컨테이너 적용은 VM에서 수동으로 실행합니다.

```bash
docker compose pull
docker compose up -d
```

## OpenCV Docker

OpenCV 앱 이미지는 무거운 의존성을 미리 담은 base image를 사용하도록
정리했습니다.

```txt
kkmin1106/bitemateopencv-base:py312-yolo
```

이 base image에는 Torch, Ultralytics, OpenCV, numpy, apt runtime libraries가
들어갑니다. 일반 코드 변경 시에는 앱 이미지만 다시 빌드하면 됩니다.

base image 빌드:

```bash
docker buildx build --platform linux/amd64 \
  -t kkmin1106/bitemateopencv-base:py312-yolo \
  --push ./opencvbase
```

## VM 디스크 부족

OpenCV/Torch 이미지가 커서 VM에서 아래 오류가 발생했습니다.

```txt
no space left on device
```

확인 명령:

```bash
df -h
docker system df
sudo du -sh /var/lib/docker /var/lib/containerd /home/dongmin /var/log
```

정리 명령:

```bash
docker system prune -af
docker builder prune -af
sudo systemctl restart docker
```

DB는 외부 Oracle을 사용하므로 중요한 로컬 Docker volume이 없다면 unused
volume도 정리할 수 있습니다.

## 브라우저 웹캠 CCTV 방식

Azure VM은 사용자 PC에 연결된 웹캠을 직접 열 수 없습니다. 그래서 브라우저가
웹캠 프레임을 캡처해서 서버로 업로드하는 방식으로 결정했습니다.

```txt
브라우저 웹캠
  -> POST /api/cctv/frame
  -> Spring Boot가 OpenCV /api/v1/inference/image로 전달
  -> Spring Boot가 PEOPLE_LOG 저장
```

이 방식은 `storeId`를 함께 보내므로 매장별 데이터 분리가 가능합니다.

## OpenCV 네트워크 규칙

Docker Compose 내부에서는 아래 값을 사용해야 합니다.

```env
FASTAPI_BASE_URL=http://opencv:8000
FASTAPI_DOCUMENT_OCR_URL=http://opencv:8000/api/v1/documents/ocr
```

`127.0.0.1:8000`은 백엔드 컨테이너 자기 자신을 의미하므로 사용하면 안 됩니다.

## AI 스케줄 timeout

공통 axios timeout은 10초입니다. AI 스케줄 생성은 10초 이상 걸릴 수 있으므로
월별 근무표 화면에서 `/shift/ai-preview` 요청만 60초 timeout으로 변경했습니다.

## AI 운영 추천 주의점

메인 대시보드 추천 문구가 실제 데이터 기반인지 확인해야 합니다.

실제 데이터 기반으로 볼 수 있는 항목:

- people_log 고객 수
- shift 근무표
- QR 출퇴근/근태 데이터
- 대타 모집 데이터
- 문서 만료 데이터

고객 연령대, 메뉴 선호도, 프로모션 추천은 POS/회원/고객 통계가 연결되어야
실제 분석으로 볼 수 있습니다. 현재 데이터가 없으면 샘플 또는 fallback으로
표시해야 합니다.
